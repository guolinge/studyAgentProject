# 作图规范（字符图 ASCII，飞书等宽代码块兼容）

所有字符图以**纯 ASCII 字符**产出，放入飞书 Markdown 围栏代码块（````  ````）。飞书等宽渲染器下**中文字符占 2 列宽**，对齐极易崩，故必须严格遵守下面所有约束。

---

## A. 硬约束（违反 = 渲染失败 / 乱码）

1. **允许字符集**（仅此）：
  - 框线：`+`（拐角/交叉） `-`（水平线） `|`（垂直线）
  - 箭头：`>` `<` `^` `v`
  - 斜线：`/` `\` **少用**，仅在决策菱形或示意斜向时使用
  - 空格、英文字母、数字、标准标点（`,` `.` `:` `(` `)` `_` `#` `=`）
2. **禁用字符**（一律禁止，含任何 Unicode 制表符 / 装饰符）：
  ```
   ┌ ┐ └ ┘ ─ │ ├ ┤ ┬ ┴ ┼
   ╔ ╗ ╚ ╝ ═ ║
   ╭ ╮ ╰ ╯
   ▶ ▼ ◀ ▲ ● ○ ◆ ◇ → ← ↑ ↓ ⇒ ⇐
  ```
   只要粘贴到等宽字体环境中会移位的字符，全部禁止。
3. **中文 / 全角字符按 2 列宽计算**：
  - "服务" = 4 列，"数据库" = 6 列，"API 网关" = 2+1+2+1+2 = 8 列（注：`A``P``I` 各 1 列，空格 1 列，"网关" 4 列）
  - 框内容行宽 = Σ(中文字×2 + 英文字×1 + 空格×1)
  - 边框宽 = 内容行宽 + 2（左右各 1 空格）+ 2（左右各 1 `|`）
  - **框的上下边框 `-` 条数 = 内容行宽 + 2（含两侧空格，不含 `+`）**
4. **宽度限制**：默认 ≤ 80 列，最大 ≤ 100 列（中文按 2 列数）。

---

## B. 三阶段工作流：PLAN → DRAW → VERIFY

### PLAN（落笔前必做）

1. **列出所有节点和标签**，逐字计算列宽（中文×2，英文×1）。
2. **计算每个框的尺寸**：
  - 内容列宽 = max(各行文字列宽)
  - 框总宽 = 内容列宽 + 4（左右各 1 空格 + 左右各 1 `|`）
  - 上下边框 = `+` + `-`×(内容列宽+2) + `+`
3. **建列标尺**：在草稿纸/注释里标记每个竖向元素的起始列号，确保同层框左对齐或均匀分布。
4. **规划连线路径**：横线从框边 `+` 引出，竖线在固定列落下，交叉处补 `+`。

### DRAW（按列位落字）

- 先画所有框体（顶边 → 内容行 → 底边）。
- 再画连线，逐行逐列检查交叉点是否为 `+`。
- 最后放箭头，确保箭头紧贴线端或框边，无悬空。

### VERIFY（画完后逐项自检，不通过不产出）

见 **D 节自检清单**，每项打勾后方可产出。

---

## C. 绘制约定

1. **Junction（交叉/分岔）规则**：
  - 每条 `|` 进入或离开横线处，该列**必须**有 `+`。
  - 横线与竖线相交处（T 形、十字形）全部用 `+`，不能用 `-` 或 `|`。
2. **箭头规则**：
  - `>` `<` 必须紧接水平线末端，或紧贴框边，前一格必须是 `-` 或 `|`。
  - `^` `v` 必须紧接竖线末端，或紧贴框边，相邻格必须是 `|`。
  - **禁止悬空箭头**（前后无线/框的独立 `>` `<` `^` `v`）。
3. **框内文字**：
  - 左右各留 ≥ 1 空格：`| 内容 |`。
  - 同层级所有框保持**等宽**（内容不足时右侧补空格）。
  - 多行内容框：每行独立计算对齐，框宽取最宽行。
4. **连线标签**：
  - 放在连线旁（上方或右侧），说明关系（如"调用""返回""触发"）。
  - 标签不得覆盖线条本身，应偏移 1 行。
5. **斜线使用**（仅限决策菱形）：
  ```
     +-------+
    /  判断?  \
   +           +
    \         /
     +-------+
  ```
   其余场景用正交线（水平 + 垂直）替代斜线。

---

## D. VERIFY 自检清单（逐条打勾）

画完每张图后必须对照以下清单，全部通过才产出：

- **无禁用字符**：图内不含任何 Unicode 制表符、装饰符、特殊箭头。
- **行宽合规**：每行 ≤ 100 列（中文按 2 列数）；目标 ≤ 80 列。
- **Junction 完整**：每个 `|` 进出横线处都有 `+`；横竖交叉处都有 `+`。
- **无悬空箭头**：所有 `> < ^ v` 前后均紧贴线条或框边。
- **同层框等宽**：同一层级的框宽度相同，内容不足处用空格补齐。
- **上下边框对齐**：框的 `+---+` 与内容行的 `| ... |` 列数严格一致。
- **中文框宽正确**：含中文的框宽已按「中文×2 + 英文×1」算准，上下 `-` 条数与内容行宽度匹配。
- **连线标签不压线**：边标签未覆盖 `-` 或 `|` 字符。

## F. 反例（错误 → 修正）

### F1. 禁用 Unicode 制表符（错 vs 对）

**❌ 错误**（使用了 Unicode 制表符，会在等宽字体环境乱码）：

```
┌──────────┐
│  用户请求 │
└──────────┘
     │
     ▼
┌────────┐
│  服务  │
└────────┘
```

**✅ 修正**（全部替换为允许字符集）：

```
+----------+
| 用户请求  |
+----------+
     |
     v
+------+
| 服务 |
+------+
```

---

### F2. 中文标签按 1 列算导致边框错位（错 vs 对）

**❌ 错误**（把"用户请求"当作 4 个字符 = 4 列，画了 `+----+`，只有 6 字符宽）：

```
+------+      （错：把中文4字按4列算，内容6=4+两空格，边框+6个-+）
| 用户请求 |   （实际渲染：|+1空格+8列+1空格+| = 12列，边框却只有8列，对不上）
+------+
```

渲染效果（错位）：

```
+------+
| 用户请求 |
+------+
```

注意：上下 `+------+` 只有 8 列宽，但内容行 `| 用户请求 |` 实际渲染 12 列，**右侧框线悬空在外**。

**✅ 修正**（"用户请求"= 4字×2 = 8列，内容宽 8，两侧各 1 空格 = 10，上下边 10个`-`）：

```
+----------+
| 用户请求 |
+----------+
```

验证：`+----------+` = 1+10+1 = 12 列；`| 用户请求 |` = 1+1+8+1+1 = 12 列 ✓
