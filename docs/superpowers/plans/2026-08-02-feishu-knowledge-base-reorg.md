## 背景

用户的飞书文档积累了大量学习笔记，分散在 6 个顶级文件夹中，存在以下问题：
- `每日任务` 是最大的乱堆场，装了 50+ 个学习专题，命名极具误导性
- 大量重复文件夹（数据库专题×3、网络专题×2 等）
- 命名不规范：格式混乱、模糊词泛滥、英文技术名不用官方大小写
- 无统一入口，找资料需记忆 6 个分散位置

## 执行阶段

### Phase 1：创建新文件夹骨架
在根目录创建"技术知识库"及所有子文件夹（约 25 个）。

### Phase 2：迁移现有顶级文件夹
- 移动并重命名：计算机系统 → 技术知识库/计算机系统原理
- 移动并重命名：数据库 → 技术知识库/数据库（内部子文件夹按新名重命名）
- 移动并重命名：Go相关的 → 技术知识库/Go 语言
- 移动并重命名：AI专题（内容分流到 大模型原理 + 工具与效率）

### Phase 3：拆散"每日任务"
将每日任务下所有学习专题文件夹按类别移入技术知识库对应位置。
重复文件夹（数据库专题×3等）：内容移入主文件夹后，空文件夹放入"待清理"等用户手动删除。

### Phase 4：agent 自动更新索引（代码改动）
在 pipeline 发布后，追加一行到总索引文档：`|标题|分类|链接|日期|`
需要在 orchestrator/cli 中增加 `updateIndex` 步骤，存储索引文档 token 到 `.env`。

## 命名规范

1. 英文技术名用官方大小写（React、TypeScript、webpack、Vite、pnpm）
2. 去掉"专题/专项"后缀，文件夹名即知识域
3. 不中英混拼（bff → BFF，seoCms专题 → 移入公司项目）
4. 中文分类词简洁准确，不用"自己的理解""杂七杂八"
